## Главные выводы в трёх пунктах

### 1. Ветки связаны линейно, а не параллельно

```text
main (b085ad3)
  └── +94 коммита ──> codex-1 (a0ebe8a)
                        └── +49 коммитов ──> codex-2 (5dbd43e)
```

`codex-2` содержит каждую строку `codex-1`. Между ними изменено **0 строк** детерминированного
пайплайна — вся разница в новом пакете `review/`. Выбирать между ними как между альтернативами
некорректно. Подробно: [03](03_BRANCH_ANALYSIS.md).

### 2. Слой ревью `codex-2` не может изменить ответ

Доказано по коду: `_validate_decision` отвергает любое решение ревьюера, где число, вердикт или
доказательство отличаются от детерминированного ответа; `authoritative_results` возвращает нетронутый
вход; сериализатор читает `CovenantResult` напрямую.

Следствие: для любого ковенанта тройка `(вердикт, число, доказательство)` **побитово идентична** вне
зависимости от того, запускался слой ревью или нет. Подробно: [06](06_CODEX_1_VS_CODEX_2.md).

### 3. Проверочное усилие направлено не туда

```text
                     обнаружение  интерпретация  исполнение
                     ───────────  ─────────────  ──────────
частота ошибок          высокая      высокая        низкая
как проявляются       молчаливо    молчаливо       громко
проверок в codex-1/2      нет      почти нет     четыре слоя
```

Ошибки исполнения падают с исключением и фиксируются. Ошибки обнаружения и интерпретации дают
аккуратный неверный ответ, который выглядит правильным. Проверки стоят там, где ошибки и так себя
обнаруживают. Подробно: [10, §2](10_WHY_CLOUD1.md#2-где-на-самом-деле-теряются-баллы).

## Что предлагает Cloud1

Один архитектурный ход и одиннадцать точечных исправлений.

**Ход:** ревьюера из `codex-2` перенести с позиции «после вычисления» на «до вычисления», и с вопроса
«правильный ли ответ?» на вопрос «правильно ли записано правило?».

```text
codex-2:   спецификация → ЧИСЛО → вердикт → ревьюер → файл → ✗ ничего

Cloud1:    спецификация → ревьюер → отклонено? → перекомпиляция ┐
                ↑                                              │
                └──────────────────────────────────────────────┘
                              ↓ принято
                           ЧИСЛО → вердикт → ответ
```

Результат по трём осям одновременно:

| | codex-2 | Cloud1 |
| --- | --- | --- |
| Вызовов LLM на ревью | `P … 2P` за каждый прогон | `C … 2C` всего, кешируется |
| Пример (12 ковенантов, 40 пар, 3 прогона) | 120 … 240 | 12 … 24 |
| Защита ревьюера | валидация из 30 строк | тип решения без числовых полей |
| Влияние на балл | ноль по построению | прямое |

Дешевле, безопаснее и при этом единственный вариант, способный ответ улучшить. Подробно:
[09](09_ARCHITECTURE_CLOUD1.md), обоснование: [10](10_WHY_CLOUD1.md).

## Правила работы в этом треке

```text
main, codex-1, codex-2   —  не изменяются ни при каких условиях
рабочая ветка            —  covenant-architecture-v3 (базируется на codex-2)
содержимое ветки         —  только markdown в docs/architecture-v3/
merge и PR               —  только по отдельному явному запросу
```

Почему база `codex-2`, а не `main`: `codex-2` — строгое надмножество, содержит полный текущий
пайплайн. База `main` отбросила бы 143 коммита, база `codex-1` — слой ревью, который входит в предмет
аудита.
