## 0. Стратегия

### Главное ограничение

**27 тестовых файлов импортируют `CovenantSpec` [OBS].** Изменение типа на месте ломает их разом
и оставляет репозиторий сломанным на всё время миграции. Это недопустимо по условию задачи.

### Выбранный подход: параллельная модель, поэтапный перевод потребителей

```
CovenantRule добавляется РЯДОМ с CovenantSpec, а не вместо него.
Потребители переводятся по одному.
CovenantSpec удаляется, когда потребителей не осталось.
```

Репозиторий остаётся зелёным после каждого шага. Цена — временное сосуществование двух моделей;
она оправдана: альтернатива — недели красных тестов.

### Порядок фаз и почему он отличается от типового

Типовой порядок ставит контракты первыми. Здесь **первым идёт скорер**, и это принципиально:

> `ground_truth.json` содержит все 36 ответов. Пока нет скорера, ни один последующий шаг
> не проверяем ничем, кроме мнения. Со скорером каждый шаг измеряется числом.

Ошибка, приведшая к переписыванию, состояла именно в отсутствии измеримости. Скорер — первое,
что нужно построить.

```
Ф0  Страховка              зафиксировать зависимости, разделить тесты, снять базовый замер
Ф1  Измеримость            скорер по ground_truth + манифест из шаблона
Ф2  Доменная модель        новые типы РЯДОМ со старыми
Ф3  Загрузка               реальные источники
Ф4  Интерпретация          маршрутизация, извлечение, категоризация, компиляция
Ф5  Расчёт                 оценка, улика, верификация
Ф6  Сборка                 сквозная команда, перевод потребителей
Ф7  Удаление legacy        в порядке зависимостей
Ф8  Конфигурация и доки    Docker, CI, README
```

```

Q5  доля операций с определённой категорией    ≥ 0.95

```
