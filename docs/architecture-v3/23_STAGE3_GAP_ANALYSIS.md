## 2. Findings по десяти заданным осям

### 2.1 Неправильные границы абстракций

| Что | Проблема |
| --- | --- |
| `FilterSpec` ↔ физические колонки | Абстракция «фильтр» проведена по уровню хранения, а не предметной области. Ковенант говорит о *категориях*, а тип умеет только *колонки*. Граница проведена на этаж ниже, чем нужно |
| `evaluators` ↔ `evidence` | Селектор улики вызывается изнутри вычислителя (`base.py`), хотя это отдельное решение. При новой семантике («убрать → пересчитать») потребуется доступ к пересчёту, то есть инверсия |
| `synthetic` → `pipeline` | Mock-слой импортирует production-оркестратор. Направление зависимости обратное правильному: тестовые данные не должны знать о конвейере |
| `covenants/temporal` ↔ документ | Версионирование живёт на уровне спецификации, а реальная версионность — свойство **документа** |

### 2.2 Модели, копирующие формат mock вместо предметной области

| Модель | Признак копирования |
| --- | --- |
| `Transaction` | 11 полей = ровно колонки `synthetic_transactions.xlsx`, включая `direction`, которого нет ни в одном реальном источнике |
| `CANONICAL_COLUMNS` в `storage` | Тот же список, продублирован |
| `PHYSICAL_TRANSACTION_FIELDS` | Тот же список, продублирован третий раз |
| `CovenantResult.verdict` | Словарь придуман под MVP, не сверен с требованием |

## 3. Mock assumptions that must die

```
1.  колонка direction                       → знак суммы, и он НЕ равен направлению
2.  положительная сумма = выручка           → контр-проводки [OBS]
3.  категория выразима фильтром по колонке  → категории нет ни в одной колонке
4.  существует справочник заёмщиков         → scenario_id выводится из txn_id
5.  covenant_id вычисляется системой        → задан шаблоном как номер пункта
6.  вердикт complied/violated               → COMPLIANT/BREACH
7.  number со знаком                        → actual строго положительный
```
